# Dell XPS 13 9350 (Lunar Lake, IPU7) — step by step

Tested: Ubuntu 26.10, kernel 7.3.0-10-generic, BIOS 1.23.0, Secure Boot **off**.
Run commands from the repository root. Reboot when told to — never reload camera drivers live.

## 0. Check the starting point

```bash
sudo apt install v4l-utils libcamera-tools
scripts/check-cameras.sh
```

Expected before the fix: `ov02c10` loaded but **no `v4l-subdev` for `ov02c10`**, and
`pending_async_subdevices` listing `HIMX1092`.

## 1. HM1092 IR sensor driver (fixes both cameras)

```bash
sudo apt install dkms linux-headers-generic          # or your kernel's headers metapackage
sudo cp -r dkms/hm1092-dell /usr/src/hm1092-dell-1.1
sudo dkms install hm1092-dell/1.1
```

If Secure Boot is **on**, DKMS signs the module with the MOK key and you must enroll it
(`sudo mokutil --import /var/lib/shim-signed/mok/MOK.der`, then reboot and confirm in the blue MOK screen).

## 2. Keep camera drivers out of the initramfs

```bash
sudo cp config/xps13-9350/dracut/90-camera-not-in-initramfs.conf /etc/dracut.conf.d/
sudo update-initramfs -u
sudo lsinitrd /boot/initrd.img-$(uname -r) | grep -iE 'ipu7|ipu-bridge|cvs|ov02c10|hm1092'   # expect no output
```

**Reboot.** Then `scripts/check-cameras.sh` should show nothing pending, `v4l-subdev` nodes for
`hm1092` and `ov02c10`, and `cam -l` listing `\_SB_.LNK0` (IR) and `\_SB_.LNK1` (RGB).

The IR illuminator (`/sys/class/leds/HIMX1092_00::ir_flood_led`) turns on by itself only while the
IR camera streams.

## 3. Desktop (user config, no sudo)

```bash
mkdir -p ~/.config/wireplumber/wireplumber.conf.d ~/.config/systemd/user/wireplumber.service.d
cp config/common/wireplumber/50-hide-ipu-raw.conf       ~/.config/wireplumber/wireplumber.conf.d/
cp config/xps13-9350/wireplumber/51-camera-names.conf   ~/.config/wireplumber/wireplumber.conf.d/
cp config/common/systemd-user/wait-for-camera.conf      ~/.config/systemd/user/wireplumber.service.d/
systemctl --user daemon-reload && systemctl --user restart wireplumber
wpctl status | sed -n '/^Video/,/^Settings/p'      # Sources: "Front Camera" (default), "IR Camera"
```

The GNOME Camera app now works. View the IR camera:
`gst-launch-1.0 pipewiresrc target-object=libcamera_input.__SB_.LNK0 ! videoconvert ! autovideosink`

## 4. Chrome / Google Meet (optional)

Enable `chrome://flags/#enable-webrtc-pipewire-camera`, then:

```bash
scripts/grant-chrome-camera.sh
```

Restart Chrome; in Meet choose **Front Camera**.

## 5. Zoom and other V4L2-only apps (optional)

Needs the **patched** v4l2-relayd (see [patches/v4l2-relayd](../patches/v4l2-relayd/)):

1. Build and install the patched relay: follow [patches/v4l2-relayd/README.md](../patches/v4l2-relayd/README.md)
   (it installs `v4l2-relayd`, builds the patch, and diverts the stock binary).
2. Add the instance config and hide the virtual device from PipeWire:

```bash
sudo mkdir -p /etc/v4l2-relayd.d
sudo cp config/xps13-9350/v4l2-relayd/webcam.conf /etc/v4l2-relayd.d/
cp config/common/wireplumber/52-hide-v4l2loopback.conf ~/.config/wireplumber/wireplumber.conf.d/
```

Reboot (loads `v4l2loopback`). In Zoom: Settings → Video → **Virtual Camera**.

## 6. Gaze face unlock (optional)

See [patches/gaze/README.md](../patches/gaze/README.md). The TPM must be enabled in the BIOS
(F2 → Security) unless you turn off template encryption. Camera settings:
[config/xps13-9350/gaze-cameras.toml](../config/xps13-9350/gaze-cameras.toml).

## Undo

| Piece | Undo |
|---|---|
| HM1092 driver | `sudo dkms remove hm1092-dell/1.1 --all` + reboot (webcam stops working again) |
| dracut file | `sudo rm /etc/dracut.conf.d/90-camera-not-in-initramfs.conf && sudo update-initramfs -u` |
| WirePlumber files | delete them from `~/.config/...`, restart WirePlumber |
| Chrome permission | `scripts/grant-chrome-camera.sh no` |
| v4l2-relayd | `sudo dpkg-divert --remove --rename /usr/bin/v4l2-relayd`; `sudo apt remove v4l2-relayd` |
